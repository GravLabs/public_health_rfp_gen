Phase 01

Prerequisites

~5 min

Install all four CLI tools before cloning the repo. Run the version checks to confirm each is ready.

Azure CLI ≥ 2.60
Used for all ARM / resource management commands.
# Linux/macOS
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

# Windows
winget install Microsoft.AzureCLI

# Verify
az version
Azure Developer CLI (azd) ≥ 1.9
Orchestrates provision + deploy + hooks in a single command.
# Linux/macOS
curl -fsSL https://aka.ms/install-azd.sh | bash

# Windows
winget install Microsoft.Azd

# Verify
azd version
.NET SDK 8
Required to build the Semantic Kernel orchestrator container.
# Linux
wget https://dot.net/v1/dotnet-install.sh && bash dotnet-install.sh --channel 8.0

# Windows
winget install Microsoft.DotNet.SDK.8

# Verify
dotnet --version   # need 8.x
Python 3.12 + Docker
Python runs the ingestion pipeline and post-provision hook. Docker builds container images.
# Python — Ubuntu/Debian
sudo apt install python3.12 python3.12-venv python3-pip -y

# Python — Windows
winget install Python.Python.3.12

# Docker Desktop: https://www.docker.com/products/docker-desktop
# Verify both
python3 --version && docker info | head -3
Phase 02

Deploy to Azure

~25 min

azd up provisions all Azure resources via Bicep, builds and pushes Docker images, then runs the post-provision hook that indexes the RFP corpus and writes .env. Go get a coffee — it takes about 20 minutes.

Clone and authenticate
git clone https://github.com/GravLabs/public_health_rfp_gen.git
cd public_health_rfp_gen

az login
azd auth login
Create environment and set required variables
azd env new pubhealth-rfp-poc
azd env set AZURE_LOCATION eastus
azd env set APIM_PUBLISHER_EMAIL "you@example.com"
azd env set OWNER_EMAIL          "you@example.com"
Deploy everything
azd up
Runs three phases automatically: Bicep provision (~15 min) → Docker build & push → post-provision hook (corpus upload, Search index, AI Foundry env vars, bot App ID restore).
Confirm Container Apps are running
RG=$(azd env get-value AZURE_RESOURCE_GROUP)
az containerapp list -g $RG --query "[].{name:name,state:properties.latestRevisionName}" -o table
You should see two rows: ca-pubhealth-api-* and ca-pubhealth-orch-*.
⚠
Use azd deploy, not azd provision, for code changes Running azd provision re-runs Bicep and can reset secure parameters. The post-provision hook restores the bot App ID, but it is slower. Only run azd provision when you are changing infrastructure.
Phase 03

Teams Bot Setup

~10 min

The bot identity is a one-time manual step — azd up provisions the Bot Service but cannot create or own an App Registration for you. Do this once; the post-provision hook preserves it on future deploys.

Create App Registration
# Creates the identity the bot uses to authenticate with Bot Framework
az ad app create \
  --display-name "pubhealth-rfp-bot" \
  --sign-in-audience AzureADMyOrg

# Note the "appId" from the output — you need it below
APP_ID="<appId-from-output>"
Create a client secret
az ad app credential reset --id $APP_ID --years 2
# Note the "password" from the output

APP_PASSWORD="<password-from-output>"
Set credentials on the API container
azd env set BOT_APP_SECRET "$APP_PASSWORD"

RG=$(azd env get-value AZURE_RESOURCE_GROUP)
API_APP=$(az containerapp list -g $RG \
  --query "[?tags.\"azd-service-name\"=='api'].name|[0]" -o tsv)
IMAGE=$(az containerapp show -n $API_APP -g $RG \
  --query "properties.template.containers[0].image" -o tsv)

az containerapp update -n $API_APP -g $RG \
  --image "$IMAGE" \
  --set-env-vars \
    "MICROSOFT_APP_ID=$APP_ID" \
    "MICROSOFT_APP_PASSWORD=$APP_PASSWORD" \
  --revision-suffix botinit \
  --output none

echo "Done — container updated."
ℹ
Always pass --image "$IMAGE" when updating env vars. Omitting it creates a stuck "Activating" revision on this Container Apps environment.
Point the Bot Service at the API endpoint
BOT_NAME=$(az resource list -g $RG \
  --resource-type Microsoft.BotService/botServices \
  --query "[0].name" -o tsv)
FQDN=$(az containerapp show -n $API_APP -g $RG \
  --query "properties.configuration.ingress.fqdn" -o tsv)

az bot update -g $RG -n $BOT_NAME \
  --endpoint "https://$FQDN/api/messages"

echo "Bot endpoint: https://$FQDN/api/messages"
Phase 04

Teams App Install

~5 min

The Teams manifest ties the Teams app to your App Registration. Update it with the App ID from Phase 3, rebuild the ZIP, and upload it to Teams.

Update manifest.json with your App ID
Open teams-app/manifest.json and replace both "id" and bots[0].botId with your $APP_ID from Phase 3.
# Quick sed replacement (or edit manually in your editor)
sed -i "s/26b9c245-880d-458b-9edf-809c1a7f534a/$APP_ID/g" \
  teams-app/manifest.json

# Verify both values updated
grep -E '"id"|botId' teams-app/manifest.json
Rebuild the app package ZIP
cd teams-app
zip -j pubhealth-rfp-bot.zip manifest.json color.png outline.png
cd ..
Upload to Teams
Two options depending on your tenant permissions:
Option A — Teams Admin Center (if you have admin access): go to Teams Admin Center → Manage apps → Upload new app, upload pubhealth-rfp-bot.zip.
Option B — Sideload (if custom app upload is enabled): in Teams, go to Apps → Upload a custom app, select pubhealth-rfp-bot.zip.
Open the bot in Teams and send a ping
Search for RFP Generator Bot in Teams → Apps → open a chat. Send hi. The bot should respond with its capability menu. If you see nothing after 10 seconds, check the API container logs.
# Tail API container logs if the bot doesn't respond
az containerapp logs show -n $API_APP -g $RG --follow
Phase 05

SharePoint Access

~5 min

Required for the "Approve & Save to SharePoint" button. The managed identity needs Sites.ReadWrite.All on Microsoft Graph. Skip this phase if you don't need SharePoint upload.

Assign Sites.ReadWrite.All to the managed identity
MI_OID=$(az identity list -g $RG --query "[0].principalId" -o tsv)
GRAPH_SP=$(az ad sp show --id 00000003-0000-0000-c000-000000000000 --query id -o tsv)
ROLE_ID="9492366f-7969-46a4-8d15-ed1a20078fff"   # Sites.ReadWrite.All

az rest --method POST \
  --url "https://graph.microsoft.com/v1.0/servicePrincipals/$MI_OID/appRoleAssignments" \
  --body "{\"principalId\":\"$MI_OID\",\"resourceId\":\"$GRAPH_SP\",\"appRoleId\":\"$ROLE_ID\"}"

echo "Role assigned to managed identity $MI_OID"
Get your SharePoint site ID
Replace contoso.sharepoint.com and /sites/yoursite with your tenant and site path.
az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/contoso.sharepoint.com:/sites/yoursite" \
  --query id -o tsv
# Output format: contoso.sharepoint.com,<site-guid>,<web-guid>
Set SharePoint env vars on the API container
SITE_ID="<output-from-above>"
IMAGE=$(az containerapp show -n $API_APP -g $RG \
  --query "properties.template.containers[0].image" -o tsv)

az containerapp update -n $API_APP -g $RG \
  --image "$IMAGE" \
  --set-env-vars \
    "SHAREPOINT_SITE_ID=$SITE_ID" \
    "SHAREPOINT_DRAFT_LIBRARY=Generated Drafts" \
  --revision-suffix sharepointinit \
  --output none

echo "SharePoint configured."
Phase 06

Verify & First Prompt

~3 min

Run the verification script to confirm every phase passed, then send your first prompt in Teams.

Run the setup verifier
Checks prerequisites, AZD env vars, container status, OpenAI deployments, search index doc count, bot credentials consistency, and fires a live smoke test against /classify.
bash scripts/verify-setup.sh
All checks should be green. Warnings on SharePoint env vars are OK if you skipped Phase 5.
Quick API smoke test (optional — before opening Teams)
FQDN=$(az containerapp show -n $API_APP -g $RG \
  --query "properties.configuration.ingress.fqdn" -o tsv)

curl -s -X POST "https://$FQDN/classify" \
  -H "Content-Type: application/json" \
  -d '{"description":"influenza surveillance program, CDC, 24 months"}' | python3 -m json.tool
Expected: {"program_area": "Influenza Surveillance", "confidence": 0.96, ...}
Send your first prompt in Teams
Open the RFP Generator Bot in Teams. You should see sections appear live in the card as each of the 8 sections completes (~2–3 min). When the gate passes, an Approve & Save to SharePoint button appears.
First prompt — paste this exactly
Draft a 24-month influenza surveillance RFP. CDC funding, $2.5M total, awards between $150K–$400K, no cost share required.
✓
You're live. Try the other four capabilities: Classify: whole genome sequencing surveillance program · Any recent CFR changes affecting public health labs? · attach a proposal PDF and say Review this proposal against RFP-2024-FLU-027 · paste a budget narrative and say Audit this budget.
ℹ
Future code changes Use azd deploy — it rebuilds and pushes only the changed container(s) without touching infrastructure. azd provision is for infra-only changes and is slower.
