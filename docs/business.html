The Problem

Public health agencies that administer federal grant programs — CDC cooperative agreements, HRSA awards, HHS emergency preparedness funds — issue dozens of RFPs per year. Today the process is almost entirely manual.

Today — Manual Process
  • Program officer drafts from memory and prior-year documents
  • Legal reviews for compliance language — days of back-and-forth
  • Finance reconciles funding parameters separately
  • 4–8 weeks per RFP cycle; bottleneck is human bandwidth
  • Inconsistent across program areas and reviewers
  • Regulatory changes often missed until post-publication
With This Platform
  • Program officer describes the RFP in plain language in Teams
  • AI drafts all 8 sections, grounded in historical award corpus
  • 5-dimension evaluation gate checks compliance automatically
  • First draft ready in under an hour; human review on a clean document
  • Consistent structure and citation format across all program areas
  • Nightly regulatory watch flags changes before they become problems

What It Does

Six AI-powered capabilities, all accessible from Microsoft Teams without leaving the tools your team already uses.

📄

RFP Drafting + Quality Gate

Generates all eight required RFP sections grounded in historical award precedents, then automatically runs five independent evaluators (completeness, parameter accuracy, compliance, groundedness, coherence). A draft only reaches the program officer if it passes all five checks.

✅

Human Approval + SharePoint Upload

After reviewing the draft in Teams, the program officer clicks Approve & Save to SharePoint. The platform assembles a fully-formatted Word document and uploads it to the SharePoint Generated Drafts library, returning a direct link — no file download required.

📋

Proposal Review

After an RFP closes, reviewers submit incoming proposals for scoring against the RFP's own evaluation criteria. Returns a structured score per criterion with evidence excerpts and a fund / do-not-fund recommendation. Supports PDF and Word file attachments.

🔍

Program Classification

Automatically maps a free-text funding request description to the correct program area before drafting begins — reducing off-topic drafts and retrieval errors for program officers unfamiliar with taxonomy.

⚖️

Regulatory Watch

Scans the Federal Register and CDC guidance channels for recent regulatory changes affecting public health laboratory programs — 2 CFR 200, CLIA, select-agent rules, and more. Returns a structured alert list with required actions.

💰

Budget Audit

Reviews submitted budget narratives against the originating RFP's funding parameters — flagging discrepancies in total award, performance period, or cost-sharing requirements before the review panel convenes. Arithmetic is verified server-side.

Who Uses It

👩‍💼
Program Officer

Starts the draft

Describes the RFP in plain language in Teams — program area, funding amount, performance period, key requirements. Reviews the AI-generated draft and approves or requests revisions. No forms, no templates, no portal to log into.

🗂️
Grants Administrator

Oversees quality and compliance

Receives drafts that have already passed the automated quality gate. Reviews evaluator scores and failure reasons when a draft is rejected. Uses the proposal review capability during the awards process to score submissions consistently.

⚖️
Compliance Officer

Monitors regulatory exposure

Receives the weekly regulatory watch digest in Teams. Reviews changes flagged against the corpus and approves updates to compliance thresholds. Audits budget narratives before review panels to catch parameter conflicts early.

🛠️
IT / Data Engineer

Deploys and operates the stack

Provisions all Azure resources with a single azd up command (~15 minutes). Manages the SharePoint corpus libraries and OneLake ingestion pipeline. Monitors cost and token usage via the built-in budget dashboard.

1

Describe the RFP in Teams

Program officer types the program area, funding amount, period, sponsor, and any special requirements in plain language. The bot classifies the request and confirms parameters before generating.

2

Watch sections appear live in the chat

The Teams card updates in real time as each of the 8 sections completes — Background, Funding Parameters, Eligibility, and so on — with a checkmark as each one finishes. Program officers see genuine progress rather than a spinner. After all sections complete, the 5-dimension evaluation gate runs automatically. The whole process takes 2–5 minutes.

3

Approve, reject, or edit — right from the card

The Teams card shows evaluation scores and an Open Draft Preview button — every card links to a pinned Teams tab (see Draft Preview below) showing the draft's actual current text, so there's no need to open the SharePoint doc just to see what changed. Three more actions are available regardless of whether the quality gate passed: Approve & Save to SharePoint assembles a properly-formatted Word document — section headings, bullet lists, and tables rendered as native Word styles — uploads it to the Generated Drafts library, and drops a direct SharePoint link in the chat. Reject marks the draft rejected with an optional reason. Edit Section expands an inline card to type a section's full replacement text and re-run the quality gate immediately, without leaving Teams — useful exactly when the gate flags an issue the program officer can fix in a sentence or two. Every generated and edited version is archived automatically (see Analytics below) — SharePoint always holds just the current approved copy, but the full revision history is never lost.

Or just tell it what to change

A section can also be rewritten by typing an instruction directly into the chat, no card required: "Edit the eligibility section to mention CLIA accreditation" resolves against whichever draft was most recently generated or edited, rewrites just that section, and comes back with the same result card, scores and all. This only fires on a message that both names an edit ("edit," "update," "revise," …) and a section — a message like "audit this budget" still goes to Budget Audit, not to an accidental rewrite.

Draft Preview — a pinned tab, not buried in chat

Editing a draft several times in a row means scrolling back through card history to see what changed. A personal Teams tab pinned next to the chat — Draft Preview — always shows the most recently generated, edited, or rejected draft's current text, formatted the same way it will look as a Word document (headings, bullet lists, and tables), and refreshes automatically. Approved drafts still get their own permanent copy in the SharePoint Generated Drafts library; this tab is for the working draft before that point, when it only exists in chat.

4

Analytics and oversight in Power BI

Evaluation scores, pass rates by program area, gate calibration metrics, and regulatory change alerts are all visible in a Power BI dashboard connected to the platform's data store — no additional reporting setup required.

Fabric is the largest production cost. The 60-day free trial covers the POC period. After the trial, the minimum Fabric capacity (F2) runs ~$400–530/month. If Power BI analytics aren't required immediately, this cost can be deferred by using standard Azure data services for the first production phase.
Three cost levers reduce model spend by ~50% overall. (1) Model routing: the evaluation gate runs on GPT-4o-mini (~93% cheaper than GPT-4o) — structured scoring tasks don't need the full model. (2) Section-tiered generation: 3 of 8 RFP sections (reporting requirements, budget requirements, submission instructions) are boilerplate and generated on GPT-4o-mini; the remaining 5 creative/grounded sections use the fine-tuned GPT-4o. (3) Prompt caching: all 8 section calls share the same system message prefix (parameters + grounding context); Azure OpenAI caches it after section 1, cutting prompt token cost ~50% for sections 2–8.
POC column is measured, not estimated — pulled directly from Azure Cost Management for the POC resource group, cross-checked against Azure's published meter rates. The Production column remains a projection, since that volume of usage hasn't happened yet. The API Gateway line jumped once real numbers replaced the earlier guess: API Management Standard v2 (needed for the caller-identity checks and per-caller budgets described above) runs $0.9589/hour — about $700/month for one unit — not the ~$0–5/month a Consumption-tier estimate had assumed.
POC budget headroom. At a measured ~$780–800/month against the $2,500 ceiling, the POC phase leaves roughly $1,700–1,720 of room — enough to absorb heavier testing, a partial pilot rollout, or the API Gateway's fixed cost without re-tuning the budget alert.
Real measured cost per draft: $0.04–0.06, varying with section length (measured directly from live token usage — not an estimate). At that rate, generating and evaluating a full RFP draft costs roughly the same as a cup of coffee split ten ways.

Adapting for Your Organization

This platform is generic by design. The corpus, compliance rules, program taxonomy, and evaluator thresholds are all configurable without changing the underlying platform.

  • Replace the corpus — swap the 50 sample RFPs with your organization's actual historical award documents in any format (PDF, Word, Markdown)
  • Add compliance rules — extend the compliance evaluator with organization-specific required phrases or prohibited terms
  • Change program areas — update the taxonomy to match your grant program structure; the classification agent adapts automatically
  • Tune thresholds — each of the 5 evaluators has an independent pass threshold that can be adjusted based on your quality standards
  • Add evaluators — the gate is extensible; add readability, format compliance, or budget narrative evaluators without changing the core pipeline
